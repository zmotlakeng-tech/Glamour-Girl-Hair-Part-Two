# Glamour Girl Hair Website Project

A five-page website for Glamour Girl Hair, a South African human hair brand (bundles, wigs and
professional installs) serving Durban and Johannesburg.
**Part 3 (Enhancing Functionality and SEO)** adds JavaScript interactivity, working forms with
validation, an interactive map, search engine optimisation and deployment.

- Live site: `https://glamour-girl-hair.netlify.app` *(replace with your real deployed address, see "Deployment")*
- Colours: juniper green `#2F4A3D` and sage green `#7C9473` (with a darker sage `#5F7355` for text and buttons so they stay readable)

## Part 3: What Was Added

### 1. Interactive elements (JavaScript, no libraries needed)
| Feature | Where | How it works |
|---------|-------|--------------|
| **Tabs** | Home: "Explore Our Hair Textures" | `main.js`. Follows the WAI-ARIA tabs pattern: arrow keys, Home/End, `aria-selected`. Each panel links to the products page pre-filtered by texture. |
| **Accordion** | About: FAQ | `main.js`. Buttons with `aria-expanded`, one answer open at a time, smooth open/close animation. |
| **Modal / lightbox gallery** | Home gallery + every product photo | `lightbox.js` on a native `<dialog>`: previous/next, arrow keys, Esc, click outside to close, counter, caption, focus returns to the picture you opened. |
| **Animations and transitions** | Site-wide | CSS transitions on buttons, cards and images; hero text fade-up; sections fade in as they scroll into view (`IntersectionObserver`). All animation is switched off for visitors who set "reduce motion". |
| **Interactive map** | Contact | `map.js` with Leaflet + OpenStreetMap: markers and popups for Durban and Johannesburg, buttons that fly to each place, "Show both", and **Find my nearest location** (browser geolocation, only when the button is pressed, distance worked out with the haversine formula). If Leaflet cannot load, Google Maps embeds are shown instead. |
| **Advanced DOM manipulation** | Products, forms, lightbox | Cards, lightbox, validation messages, enquiry response and email preview are all created with `createElement`/`textContent` (never `innerHTML`, so user text cannot inject HTML), plus event delegation, `URLSearchParams`, and conditional form fields. |

### 2. Dynamic content and search (Products page)
- Product cards are generated by JavaScript from `js/products-data.js`. To add a product, add one entry to that list.
- **Live search** (name, texture, length; every word typed must match), **texture filter**, **in stock only**, and **sort** (price, length, name).
- A live result count ("Showing 2 of 6 bundles"), a friendly no-results message with a clear button, and shareable filtered links such as `products.html?texture=curly`.
- The data is a `.js` file instead of `.json` on purpose: browsers block `fetch()` of local files, so this way the site also works when opened straight from the folder.

### 3. Forms and validation
Both forms use HTML5 attributes (`required`, `type`, `min`/`max`, `minlength`/`maxlength`, `autocomplete`, `inputmode`) **and** JavaScript validation (`validation.js` + `forms.js`).

| Check | Rule |
|-------|------|
| Name | 2 to 60 characters, letters (including accented), spaces, hyphens, apostrophes |
| Email | Valid format, up to 100 characters |
| Phone | South African format (`0821234567` or `+27821234567`, spaces and dashes allowed). Optional, but **required** if the visitor wants a WhatsApp or phone reply |
| Date (needed by) | Real calendar date, from today up to 12 months ahead |
| Quantity | Whole number from 1 to 10 |
| Message | Enquiry: 10 to 500 characters. Contact: 20 to 1000 characters. Live character counter |
| Dropdowns / radio / consent | Must be chosen / ticked |

Error handling: messages appear next to the field (with a "!" icon, so colour is not the only signal), fields are marked `aria-invalid`, a summary at the top lists every problem with links to the fields, and focus moves there. Fields are checked when you leave them and re-checked as you fix them. The space for each message is reserved so the form never jumps while you click.

**enquiry.html** (enquire about services/products)
1. Visitor picks what they are interested in. Choosing **Bundles** reveals the bundle and quantity fields (and a live "Estimated total").
2. On a valid submit the page **processes the input immediately** and shows a response: for bundles, the estimated total and availability (In Stock / Low Stock, with a message that depends on the quantity); for wigs and installs, how quoting works.
3. At the same time the enquiry is **sent in the background with AJAX (`fetch`)**, with no page reload, to the address in `data-ajax-endpoint` ([FormSubmit](https://formsubmit.co/)). A status line shows *sending / sent / could not send*. If the visitor is offline, the estimate still shows and a WhatsApp button lets them send it anyway.
4. The form's `action` attribute points to the same service so it still works if JavaScript is switched off.
5. Arriving from a product card (`enquiry.html?product=curly-16`) pre-selects that bundle.

**contact.html** (general message to the organisation)
1. Collects name, email, optional phone, preferred reply method, message type, subject and message.
2. On a valid submit the details are **compiled into an email** (To, Subject like `[Complaint] Late delivery`, and a formatted body) and shown to the visitor.
3. The **Send email** button opens the visitor's email app with that message addressed to the recipient set in the code (`data-recipient` on the form: `hello@glamourgirlhair.co.za`). There is also a Copy button and an Edit button.

### 4. Search engine optimisation (SEO)

**Keyword research.** I looked at what a South African customer would type when looking for this business and grouped the phrases by intent:

| Intent | Keywords | Used on |
|--------|----------|---------|
| Product | human hair bundles South Africa, Vietnamese straight hair, double drawn bundles, body wave bundles, curly hair bundles, deep wave bulk hair | Home, Products |
| Service | human hair wigs, hair install, hair install booking | Home, Enquiry |
| Local | hair bundles Durban, hair bundles Johannesburg, hair store KwaZulu-Natal / Gauteng | Home, Contact |
| Trust | premium human hair, hair that lasts, never chemically treated | About, Home |

Keywords are written into headings and copy naturally (no stuffing), and each page has its own short list in `<meta name="keywords">`.

**On-page SEO**
| Item | What was done |
|------|---------------|
| Title tags | Unique per page, 60 characters or fewer, main keyword first |
| Meta descriptions | Unique per page, 120 to 160 characters, with a clear reason to click |
| Meta keywords | 5 to 7 relevant phrases per page |
| Headings | Exactly one `<h1>` per page, then `<h2>` and `<h3>` in order with no skipped levels |
| Images | Descriptive file names (e.g. `body-wave-hair-bundles.jpg`), meaningful alt text on every image, width/height set, lazy loading below the fold |
| URLs | Short, lowercase, descriptive (`/products.html`, `/enquiry.html`); texture filters use readable queries (`?texture=curly`) |
| Internal linking | Every page links to the others in the header and footer, plus links inside the content (home to products/about/enquiry, product cards to a pre-filled enquiry, FAQ answers to enquiry/products/contact) |
| Mobile-friendliness | Viewport meta tag, responsive layouts at 1024px and 640px, large tap targets, no sideways scrolling (tested at 390px wide) |
| Social sharing | Open Graph + Twitter card tags, canonical link on every page |
| Language and region | `lang="en-ZA"` |
| Local SEO | `LocalBusiness`-style structured data (schema.org JSON-LD `Store`) listing Durban and Johannesburg with coordinates; city names in headings and copy; location cards and directions links on the contact page |

**Off-page SEO plan** (these happen outside the code, so they are a plan rather than finished work)
- **Backlinks:** list the business in South African directories, ask beauty bloggers and hair stylists for reviews or features that link to the site, and link from supplier/partner pages.
- **Social media:** post gallery photos and before/after installs on Instagram, TikTok and Facebook with a link to the site; use the WhatsApp button for orders.
- **Local SEO:** create a Google Business Profile for each city (Durban and Johannesburg), keep the name/address/phone details identical everywhere, and ask happy customers for Google reviews.

**Additional requests**
- `robots.txt`: allows crawling and points to the sitemap.
- `sitemap.xml`: lists all five pages with last-modified dates and priorities.
- **Page speed:** one CSS file, scripts loaded with `defer`, images resized (the 1500 px product image is now 1000 px) and lazy-loaded, the hero image is loaded first (`fetchpriority="high"`), no JavaScript libraries on pages that do not need them (Leaflet loads only on the contact page), fonts use `display=swap`.
- **Security:** user text is never inserted with `innerHTML`; links that open a new tab use `rel="noopener noreferrer"`; form inputs have length limits; a hidden spam-trap field catches bots; `_headers` adds `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and `Permissions-Policy`; the site is served over HTTPS by the host; no passwords or private data are stored.

### 5. Accessibility
Skip-to-content link, labels on every form control, `aria-live` regions for results and errors, keyboard-operable tabs/accordion/lightbox, visible focus outlines, text colours checked for contrast, reduced-motion support, and everything still readable if JavaScript is switched off.

## Testing
- Validation rules (31 cases), product search/filter/sort (15 cases), the enquiry estimate and the email builder (15 cases) were unit-tested with Node.
- Every page was then run in a real browser (Chromium) and checked automatically: no JavaScript errors, tabs, accordion, lightbox (open, next/previous, wrap-around, Esc, backdrop click, focus return), product search/filter/sort, every validation message, the enquiry response and the contact email preview, the offline/failure paths, no broken images or links, and no sideways scrolling at mobile width.
- To check by hand: open each page in Microsoft Edge and Chrome, resize the window to phone width, and try the forms with both valid and invalid input.

## Deployment
**Netlify (drag and drop)**
1. Go to <https://app.netlify.com/drop> and sign in.
2. Drag the whole `glamour-girl-hair` folder onto the page. Netlify publishes it straight away.
3. Open *Site configuration > Change site name* and choose a name, e.g. `glamour-girl-hair`.

**GitHub Pages (alternative)**
1. Push the project to GitHub (see below).
2. In the repository, open *Settings > Pages*, choose the `main` branch and the `/ (root)` folder, and save.
3. The site appears at `https://<your-username>.github.io/<repository-name>/`.

**After deploying:** if your address is not `https://glamour-girl-hair.netlify.app`, find and replace that text with your real address in `robots.txt`, `sitemap.xml` and the `canonical`/`og:url`/`og:image` tags of the five pages. Then submit `sitemap.xml` in Google Search Console.

**Enquiry email set-up:** the first time the enquiry form is submitted on the live site, FormSubmit sends an activation email to the address in the form (`hello@glamourgirlhair.co.za`). Open it and confirm once; after that enquiries arrive in that inbox. Change the address in `enquiry.html` (`action` and `data-ajax-endpoint`) and in `contact.html` (`data-recipient`) if you use a different one.
